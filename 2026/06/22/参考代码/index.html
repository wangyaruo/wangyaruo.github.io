return acc;
},
{ storeIds: [], storeNames: [] },
);

Request.ts
整个项目的 HTTP 请求核心工具，基于 axios 封装，统一处理所有网络请求

  1. 创建 axios 实例（第 20-23 行）
    开发环境：baseURL 用 /api（走 vite 代理）
    生产环境：baseURL 用环境变量 VUE_APP_API（真实后端地址）
    超时时间统一设为 60 秒
  2. 请求拦截器 requestHandler（第 70-126 行）
    每个请求发出前，会依次做以下事情：
    ① 重复请求取消 如果请求头带了 AbortType，就用 AbortController 记录这个请求。同 URL/参数 的旧请求会被自动取消，防止重复发送。
    ② 参数净化（Truthy 模式） 如果请求头带了 Truthy，会自动过滤掉 data 和 params 中值为 null、undefined、’’ 的字段，避免传无效参数给后端。
    ③ 注入身份信息到请求头 | 请求头字段 | 来源 | 说明 | |—|—|—| | Authorization | localStorage | 用户登录 Token | | X-OMS-ORGAN | localStorage | 当前租户 Token（除租户列表接口外） | | JD-EID | Vuex store | 京东设备 ID | | ALI-EID | Cookie _ati | 阿里设备 ID | | X-PDD-Pati / X-PDD-PageCode | 设备指纹 | 拼多多埋点参数 | | VIP-EID | window.Cid | 唯品会设备 ID（LIJING 来源除外） |
  3. 响应拦截器 responseHandler（第 129-157 行）
    收到响应后，统一处理业务逻辑：
    ① 白名单直接透传 URL 包含 pdd-platform 或 bos.prod.jeoms.com 的，直接返回原始 response.data，不做处理。
    ② 配置了 notResponsePrompt 的也透传 调用方可以自己处理响应，不走通用逻辑。
    ③ 标准业务响应解析
    success === true：直接返回 data 字段（调用方拿到的就是业务数据）
    success === false：弹出错误通知，显示 errorMessage、errorCode、requestId，并 reject
  4. 错误处理器 errorHandler（第 33-69 行）
    HTTP 层面报错（非 2xx 状态码）时触发：
    场景
    处理方式
    请求被取消（CanceledError）
    静默 reject，不弹通知
    401 未授权
    跳转登录页（5秒内只弹一次，用了节流）
    403 无权限
    弹出 errorMessage
    404 不存在
    弹出提示
    503/504 服务不可用
    弹出提示
    其他错误
    弹出通用错误信息
    配置了 NoticeLimit
    抑制弹窗，直接 reject 让调用方处理
